# Galaxy S8 (SM-G950F, dreamlte) port — progress

Branch `s8-dreamlte` ports the A5XELTE work (iOS 16.7 on a Galaxy A5 2016 with
4 KiB pages, Cortex-A53, GICv2, Samsung S-Boot) to the Galaxy S8, Exynos 8895.
Observations on the phone and build results are kept apart from plans.

## Hardware facts measured on the phone (2026-10-20)

Read from TWRP (`/proc/cpuinfo`, `/proc/iomem`, `/sys/firmware/fdt`) and with
the bare-metal `s8-probe` (v2–v7) booted from BOOT:

- S-Boot enters the BOOT "kernel" at **EL1, MMU off**, x0 = DTB (`0x8A000000`),
  Image loaded around `0x800b4000`. **CNTFRQ_EL0 = 0**; the DT timer is 26 MHz.
- Boot CPU: Cortex-A53 **MPIDR 0x100**, ID_AA64MMFR0 `0x1122` (no 16 KiB
  granule), ID_AA64ISAR0 `0x11120` (no LSE). TWRP's Linux 4.4 contains the
  arm64 CPU-feature sanity check and reports no variation for the Mongoose
  cores, so no S8 core has 16 KiB pages or LSE atomics.
- GIC-400: GICD `0x10201000`, GICC `0x10202000`; virtual timer PPI 11 (INTID 27).
- PSCI 0.1 IDs (`cpu_on 0xc4000003`). From the probe, CPU_ON returns 0 but no
  secondary core ever executed the probe's entry — unsolved; start with `cpus=1`.
- Display: S-Boot framebuffer `0xcc000000`, 1440×2960 XRGB8888 (bootargs
  `s3cfb.bootloaderfb`). The panel is in command mode; writes only reach it
  after unmasking the DECON trigger: `0x1281` → `0x12860070` (as uniLoader).
- RAM: `80000000-bc7fffff`, `c0000000-ffffffff`, `880000000-8ffffffff`. The
  high 2 GiB bank has no firmware carve-outs; XNU gets it (ADT dram-base/size).
- TWRP ramoops: base `0x92000000`, 2 MiB, ecc 0, console zone `0x92080000`
  (512 KiB). Text written there in pstore format survives a forced reboot (with
  a few bit flips) and appears in `/sys/fs/pstore/console-ramoops-0`.
- Storage is UFS (BOOT `sda7`, USERDATA `sda24`, 57 GB); no S8 driver yet.

## Build pieces

- `xnu/patches/0124-dreamlte-s8.patch` (generated by
  `tools/dreamlte/apply-dreamlte.py`): S8 framebuffer/marker/boot-MPIDR macros
  in `A5XELTE.h`, used by the early console, the AppleCLCD bridge and SweetCPU;
  A5 GPIO keys off by default. The MACHINE_CONFIG stays `A5XELTE`.
- Several A5 patches were zero-context, had a stray `xnu/` prefix or wrong hunk
  counts, so `git apply` (the CI path) skipped them. They were regenerated with
  context from a locally replayed tree (`tools/dreamlte/prep-xnu-tree.sh`,
  `export-patches.sh`); `verify-ci-apply.sh` confirms that plain `git apply`
  now yields the same tree (only the staged-HFS 0031/0041 need CI staging).
- `shim/dreamlte/`: S-Boot loader. Copies the `SWEETXNU` payload from the BOOT
  ramdisk into the high bank, writes boot_args and jumps to XNU. Logs to screen
  and pstore, leaving an 8-byte slot at `0x920ff000` for XNU's entry marker.
- `tools/mkadt_dreamlte.py`: S8 ADT (iPhone X D22AP identity and /product).
- `tools/dreamlte_mkboot.py`: Samsung BOOT packer (stock header + DTBH);
  byte-identical when repacking the stock kernel and ramdisk.

   boots, not tied to the reboot method; zeroing XNU RAM in the loader did not
   help). The physical-aperture slide is random per boot → pinned to 0 on
   DREAMLTE (run 39448175183); no hang since. `pmap_startup`: 119714 pages,
   17.6 ms.
5. `Kernel data abort` (ESR 0x96000010) in `a5xelte_touch_probe`: the A5
   touch probe is on by default and maps Exynos7580 I2C/GPIO → `a5touchprobe=0`
   (and off by default on DREAMLTE in 0124).
6. **Boot 9: no panic.** CPU0 (MPIDR 0x100) initialised with SGI1, platform
   expert, AppleKeyStore/IOWatchdog/IOSurfaceRoot/HID stand-ins, BSD, AMFI,
   Sandbox, HFS, Skywalk self-tests; then `Waiting on … IOMedia … Apple_HFS`
   — the root device. Expected: there is no S8 storage driver yet.

Logs: the loader and (since run 39445481053) the kernel console are written
to the pmsg zone and read from TWRP as `/sys/fs/pstore/pmsg-ramoops-0`.

## iOS on the S8 (2026-10-20/21)

- Loader probe (`shim/dreamlte/ufs_probe.c`) read the GPT: S-Boot leaves the
  UFS host running (HCS 0xf, HCE reads 0) but the device NOT READY (02/04/02);
  START STOP UNIT ACTIVE to W-LUN 0xD0 wakes it. Ported into `sweet_ufs.c`.
- Real fix for the early hangs: arm_vm_init's pre-built L3 budget for the
  dynamic region did not include the 17 MiB framebuffer our console maps.
- iPhone X 16.7.16 root (`tools/mkiosroot.sh` + `tools/dreamlte/finish-iosroot.sh`)
  flashed to USERDATA with `tools/dreamlte/flash-chunks.ps1` (verified chunks).
- Boot 16: `hfs: mounted iOSRoot`, launchd, boot tasks, SpringBoard exec
  (aborted: no main display, AppleCLCD name match). Boot 17: AppleCLCD up,
  backboardd frames, Apple logo. Boot 18 (1125x2436 presentation): first
  SwapBegin never completed. **Boot 19 (`sweetfb_native=1`, 1440x2960): iOS
  lock screen on the Galaxy S8**, one CPU, CPU rendering, ~15 min to reach it.

## 2026-11-06 — recovery diagnosis and RAM expansion trial

- User reports that enabling Bold Text caused a respring and the display then
  stayed at the Apple logo. This is not yet evidence that USERDATA is damaged.
  At this checkpoint `adb devices` and `fastboot devices` show no phone, so no
  post-respring pmsg, filesystem check or live preference inspection is
  available. USERDATA has not been rewritten.
- The S8 has a measured firmware-free contiguous 2 GiB high bank at
  `0x880000000..0x8ffffffff`; the current ADT exposes 512 MiB of that bank.
  The remaining lower banks contain firmware carve-outs. The loader and XNU
  boot arguments currently describe one contiguous `physBase/memSize` range,
  so exposing all 4 GiB by enlarging that number would include reserved holes.
- Added `--dram-size` to `tools/mkadt_dreamlte.py` and the optional
  `DREAMLTE_DRAM_SIZE` override to `tools/dreamlte/make-boot.sh`; default stays
  512 MiB. Built an unflashed 2 GiB diagnostic image using the current kernel
  and `mali_probe=1`: `s8-ios-2g-mali-diagnostic.img`, SHA-256
  `3d0759daad297f5901d54867c055fe058fb7e1d53676f6e5ab6e3360c295266a`.
  The payload and ADT both report base `0x880000000`, size `0x80000000`.
- Also prepared a combined 2 GiB + guarded `mali_probe=2` image,
  `s8-ios-2g-mali-id-diagnostic.img`, SHA-256
  `33fb2728895af834c38f0a41e73d7be35028b7ae3ec49e4c40e234ccf3556890`.
  It only reads GPU identity if the G3D power-status register already reports
  the domain on; it does not enable power or alter clocks.
- A previous 2 GiB trial panicked in `kmem_range_init`; it predates some later
  VM layout fixes, so this image can establish whether the current kernel now
  manages the full free bank. No runtime 2 GiB success is claimed yet.
- Next when the phone is back in TWRP/ADB: save pmsg and inspect the current
  USERDATA HFS+ volume read-only; determine whether Bold Text can be reset
  without reflashing; then test the 2 GiB BOOT with rollback available. Once
  stable RAM is established, continue the measured Mali-G71 probe and driver.
